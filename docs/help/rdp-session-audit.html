Аудит серверів

Аудит RDP-сесій

RDP Session Audit 1.3.2 реконструює життєвий цикл сеансів: вхід, reconnect, disconnect, вихід із системи, тривалість і доступні клієнтські дані.

Що показує інструмент

SAFEADMINCREATES REPORTS
  • обліковий запис і Session ID;
  • початок і завершення сеансу;
  • повний час життя сеансу, connected time та disconnected time;
  • кількість disconnect/reconnect;
  • тип завершення: нормальний Log off, Disconnect або часткові дані;
  • IP, client name та джерела подій, якщо вони доступні;
  • експорт результатів у CSV та HTML.

Джерела подій

Основний журнал:

Microsoft-Windows-TerminalServices-LocalSessionManager/Operational
Event IDЗначення
21Logon
23Logoff
24Disconnect
25Reconnect
39Explicit disconnect / disconnect by another session, якщо журнал містить подію.
40Disconnect reason code, якщо доступний.

Додатково використовується RemoteConnectionManager 1149 для успішної RDP-автентифікації.

У розширеному Security-режимі аналізуються 4624 LogonType 10, 4634, 4647, 4778 та 4779.

Що означає Disconnect

Статус DISCONNECT / session left open означає, що програма не бачить нормального Log off для цього завершення. Це типова картина при закритті RDP-вікна хрестиком, але так само може виглядати втрата мережі, аварійне закриття клієнта або інший обрив.

Тому інструмент достовірно розрізняє Log off і Disconnect, але не стверджує зі 100% точністю, що конкретний Disconnect був саме натисканням на X.

Додаткові параметри

Шукати початок довгої сесії задає lookback у днях. За замовчуванням використовується 30 днів, щоб знайти початок сеансу, який стартував раніше вибраного періоду.

Security: розширено додає Security-журнал для client/auth-даних і кореляції. На серверах із великим Security-журналом цей режим працює повільніше.

Права адміністратора

Toolkit реєструє інструмент як ADMIN і запускає його з підвищеними правами. Сам GUI може спробувати прочитати Terminal Services-журнали і без elevation, але Security може бути недоступним або неповним.

Як він запускається з Toolkit

Основна оболонка не виконує великий WinForms-скрипт у своєму процесі. Замість цього Start-RdpSessionAudit.ps1 завантажує актуальний RdpSessionAudit.ps1, створює тимчасову копію в:

C:\Temp\RaccoonAdminToolkit\RdpSessionAudit

і запускає її через окремий powershell.exe -STA. Після закриття GUI тимчасовий PS1 видаляється.

Для Windows PowerShell 5.1 тимчасова копія записується як UTF-8 з BOM, щоб кириличний UI не перетворювався на «Р…». Репозиторний runtime-файл залишається UTF-8 без BOM.

Неповні дані

Якщо журнал був очищений або старі події вже перезаписані, частина життєвого циклу може бути позначена як PARTIAL. Це не помилка GUI: потрібних подій уже немає в джерелі.
