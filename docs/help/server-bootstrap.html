Підготовка нового сервера

Toolkit підключає SMB-сховище як диск Z: у поточному вході Windows, перевіряє комплект і запускає Server Base Kit.

Де знайти

4. Налаштувати та розгорнути
   → Підготовка нового сервера
      → Підключити сховище та запустити Server Base Kit

Що відбувається

  1. Перевіряються права адміністратора.
  2. Toolkit перевіряє, чи зайнята літера Z:.
  3. Якщо Z: уже підключена до потрібного сховища, використовується чинне підключення.
  4. Якщо диска немає, Toolkit підключає SMB-шару з параметром /persistent:no.
  5. Пароль запитує системна команда net use. Пароль не записується в JSON, журнал або репозиторій.
  6. Перевіряються config.json, основний скрипт і всі увімкнені інсталятори.
  7. Запускається Z:\Server_install\Install-ServerBase.ps1.

Сховище

SMB-шлях\\u292275-sub7.your-storagebox.de\u292275-sub7
Користувачu292275-sub7

Постійне підключенняНі. Диск не відновлюється автоматично після нового входу Windows.

Якщо Z: уже зайнятий

Toolkit ніколи не видаляє і не перепризначає чужий диск. Якщо Z: є локальним диском або вказує на іншу мережеву шару, запуск зупиниться з поясненням.

Перевірка комплекту

Перед запуском обов'язково перевіряються:

  • Install-ServerBase.ps1
  • config.json
  • Installers
  • кожний файл пакета з Enabled: true

Відсутній techsys.dll дає попередження, але не блокує основне встановлення.

Одночасний запуск

Не запускайте поточний Server Base Kit одночасно на кількох серверах. Каталог Work спільний, а основний скрипт очищує і повторно створює робочі підкаталоги під час розпакування.

Наступний етап розвитку комплекту: локальний робочий каталог для кожного сервера або підкаталог із назвою комп'ютера.

Безпечна перевірка без встановлення

При прямому запуску модуля параметр -ValidateOnly підключає диск і перевіряє весь комплект, але не запускає інсталятори:

.\Start-ServerBaseKit.ps1 -ValidateOnly

Відключення диска

За замовчуванням створений Toolkit диск залишається до завершення поточного входу Windows. Відключити його вручну:

net use Z: /delete /y

При прямому запуску модуля доступний параметр -DisconnectAfterRun.

Журнали

Основний комплект продовжує зберігати журнали у:

Z:\Server_install\Logs

Результати створення користувачів і RDP-файли залишаються в каталозі Result.
